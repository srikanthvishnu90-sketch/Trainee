# 1v1: Trainee vs the architect's gold replies (2026-11-01, hardened 2026-11-02)

Owner request, 2026-11-01: compare the architect and Trainee one on one, and get Trainee to reply the same way, with links given the way Instinct gives them.

120 first-week scenarios (`evals/career/one-v-one/scenarios.ts`) across every feature, each with a channel (iMessage, SMS, WhatsApp, Telegram, web) and an account state (new, profile on file, tasks in flight). The gold reply for each was written by hand by the architect (Claude, in session; no model call, no Anthropic API spend). Every scenario carries a rubric a script checks (`score.ts`): bubble count and length, markdown, links present / alone on their own line after the line that says what they are / only real links, question count, numbered options, required facts, forbidden claims, and voice (filler, banned phrases, emoji, internal jargon). The link and formatting rules follow the owner's requirement docs Q73-Q95, Q581-Q587 and Q632-Q633 (cited by number only).

Trainee's side: trunk's live path in-process (`run.ts`): the scenario's state seeded, prior turns run, then the turn through the handler's code turns in the handler's own order (`evals/career/world.ts` CODE_TURN_ORDER, checked against handler-career.ts by test; the turns that need a live service are listed with the reason) and the router, rendered by each channel's own adapter (`channel_registry.ts`). `CAREER_TEXTING_NATIVE` off is what ships by default; on is the texting voice the owner can switch on. Free, deterministic: `deno run -A --no-check evals/career/one-v-one/run.ts --label <label>`.

## Judge and real brain (the numbers that count)

A scenario counts as passed only when the regex rubric AND an OpenAI judge pass it (`judge.ts`: gpt-4.1-mini, temperature 0, fixed seed, strict JSON schema, judged twice; a parse failure, an error or a disagreement is a FAIL). The real-brain mode (`--brain staged-real`) answers the turns the staged brain takes with the real model (gpt-5-mini) through agentTurn, the rest by code and the router, as live. Estimated spend per run: judge about $0.20, real brain about $0.25; the recorded spend is the meter's, written to `evals/career/results/1v1-<label>.json`, where the brain-eval budget counts it.

NOT RUN in this PR: the architect does not start paid runs from a session. They run in the brain-eval workflow (`.github/workflows/brain-eval.yml`, step "1v1"), under its EVAL_BUDGET_USD cap, when the owner dispatches it. Until then the regex numbers above are a floor check, not a score.

Staged brain (`CAREER_BRAIN=staged`), FAKE MODEL, no spend. This does NOT measure the brain: a model that answers with the gold text shows only whether a good reply survives the brain's delivery path and the render.

Staged brain (`CAREER_BRAIN=staged`, fake model, no spend): it would take 54/120 of these turns (the rest stay with code and the router). With a model that answers with the gold text, the delivered reply still passes its rubric in 48/54. The 6 that do not (V011, V019, V022, V023, V035, V115) lose a pay figure or a posting the fake model stated without calling a tool: the fact guard dropping an unsourced number, as it should (a real turn calls search_jobs first). On the 46 of those turns that go out on a texting channel, the system prompt carries the texting rules (plain text, each link alone on its own line, short bubbles, one question) in 0/46 before and 46/46 after.

## What this branch changed (each with a fail-first test in `tests/architect/one-v-one-texting.test.ts`)

1. Links: a link inside a sentence now goes on its own line right after the sentence that names it (`channel_voice.ts` linksOnOwnLine reads a line sentence by sentence, never splitting open bold, italics or code). Before, the three postings' sentences came first and their three links after, so no link sat under its posting.
2. Numbered roles: the router's search list numbers its roles 1), 2), 3) (`142-career-router.js` roleSentence; ")" because the composer reads "1." as a sentence end), so the person can answer with a digit.
3. Bubble length: on iMessage and SMS a reply is split between paragraphs, lines and sentences into bubbles of at most 320 characters (a single sentence longer than that stays whole, in the 700-character bubbles as before) (`channel_voice.ts` imessageNativeRender).
4. Dates: texting channels show "Oct 19, 2026", never 2026-10-19; links and code untouched (`channel_voice.ts` humanDates).
5. Staged brain: on a texting channel the system prompt carries the texting rules (`prompt.ts` textingRulesFor), and the channel reaches it (`career_brain.ts` channel, one line in `handler-career.ts`, `world.ts`). Web and no-channel prompts are byte-identical to before.
6. Style (owner brief, observed; `style-targets.json`): iMessage/SMS bubbles also carry at most 3 sentences (`channel_voice.ts` sentenceTexts), and the brain's texting rules give the numbers (3 sentences a bubble, 15-20 words a sentence, never over 25, 8th-9th grade words). WhatsApp and Telegram keep their message contract (#301: one answer in at most two messages; tables and headings whole), so there the sentence budget is the brain's rule, not a cut.

Fixes 1, 3, 4 and 6 are in the texting voice, which ships only with `CAREER_TEXTING_NATIVE=on` (an owner secret; off keeps the delivery tests' "unchanged" contract). Fix 5 matters only with `CAREER_BRAIN=staged`. Fix 2 is live on every path. (A crisis-phrase change was taken out on review: #354 owns the shared detector; V120 is left to it.) No reply prose was added to make a check pass; the words stay the router's or the model's.
